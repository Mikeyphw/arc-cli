# arc-cli Devtool wrapper

`arc-cli` uses a repository-owned Devtool contract in `.devtool.toml` and managed `devtoolw` launchers. The config is generated separately from integration overlays and must be committed before applying them so Devtool's isolated transaction worktree can see it. The repository is intentionally pinned to the **native Termux host execution environment** for its `arc` target, so Devtool uses host Python rather than routing this Python project into the configured chroot.

The launcher is generated by Devtool and delegates back to the canonical CLI/EXO runtime; it does not implement a second scheduler:

```sh
./devtoolw --help
./devtoolw setup
./devtoolw test --profile quick
./devtoolw check
./devtoolw quality
./devtoolw r06
./devtoolw r07
./devtoolw r08
./devtoolw r09a
./devtoolw r09b
./devtoolw r09b-gate
./devtoolw r10-gate
./devtoolw r11-gate
./devtoolw r12
./devtoolw r12a
./devtoolw r12-gate
./devtoolw refresh-install
./devtoolw release
./devtoolw gate
./devtoolw seal
```

## Host-Python policy

The target declares `execution_environment = "native-termux"` and the project interpreter is `python3`. Devtool's Python runner creates the repository-managed `.devtool/venvs/arc` virtual environment from that host interpreter. This is still host execution; the venv isolates project/validator dependencies without using PRoot/chroot Python.

An explicit Devtool CLI execution override remains authoritative when intentionally qualifying the repository on another machine.

## Commands

- `setup` — restore/synchronize the Devtool-managed Python environment.
- `build` / `b` — run the Python build action.
- `test` / `t` — run pytest; supports `--profile quick|integration|full`, repeatable `--node`, `--failed`, `--changed`, and `--list`.
- `lint` / `l` — run Termux's system `ruff check` and `ruff format --check`, plus completion/repository-contract checks.
- `format` / `fmt` — explicitly apply `ruff format` and `ruff check --fix` using the Termux system binary.
- `check` / `verify` / `v` — run the authoritative repository quality DAG: system Ruff checks, syntax, tests, completion/Devtool contracts, and backend smoke.
- `validate` — run Devtool's native Python validation pipeline (venv/build/test/package checks); system Ruff remains in the wrapper quality DAG because Devtool's Python lint runner intentionally executes venv modules.
- `package` / `pkg` — build and verify wheel/sdist artifacts; supports typed output path/name/collision options.
- `clean` — clean Devtool-managed artifacts, caches, and environments.
- `fast` / `f` — EXO DAG for restore, syntax, completion contract, tests, and native-backend smoke.
- `quality` / `q` — EXO DAG adding Termux system Ruff lint/format validation alongside tests and smoke.
- `r06` — run the native ARC-R06 alias/runtime/install-truth workflow and first-class test contract.
- `r07` — run the ARC-R07 explainable-plan, transaction-recovery, and resumable-batch targeted validation workflow.
- `r08` — run the ARC-R08 stable-machine-schema, typed-backend-capability, and verification-policy targeted validation workflow.
- `r09a` — run the ARC-R09A logical-fingerprint/provenance/archive-diff targeted validation workflow.
- `r09b` — run the ARC-R09B remote capability/cache/publication targeted validation workflow.
- `r09b-gate` — run the separate cumulative R09B transport capability/publication gate.
- `r10-gate` — run the separate cumulative R10 mutation policy/backend-command/machine-batch qualification gate.
- `r11-gate` — run the separate cumulative R11 configuration provenance/diagnostic qualification gate.
- `r12` — run factual format guidance, host benchmark, and redacted diagnostics bundle validation.
- `r12a` — run the gate-discovered benchmark corpus-truth completion validation (portable corpus root, empty-directory/symlink identity, real directory round trips).
- `refresh-install` / `refresh` — require generated registry/docs/completion surfaces to be current, then refresh the active editable Arc installation so all declared console scripts are present.
- `release` / `rel` — full validation, verified/reproducible packaging, backend smoke, SBOM generation, and SHA-256 release evidence.
- `gate` / `g` — run the cumulative ARC-R01 through ARC-R12 qualification gate through Devtool/EXO.
- `seal` / `s` — rerun the cumulative gate, run Devtool's wrapper final seal, compute/verify the live authoritative content root, and emit the final `SEALED` verdict.

Arguments after `--` remain native Devtool passthrough only on wrapper commands that explicitly allow it.

## EXO workflows and scheduler

The target-local jobs are:

- `syntax` — host-Python `compileall`, declared read-only.
- `ruff-toolchain` — verifies the host `ruff` executable and prints its resolved path/version.
- `ruff-check` — `ruff check src tests scripts` through the Termux host executable.
- `ruff-format-check` — `ruff format --check src tests scripts` through the Termux host executable.
- `ruff-fix` / `ruff-format-fix` — explicit mutating formatter/fix jobs used only by `./devtoolw format`.
- `completion-contract` — verifies `completions/_arc` exactly matches the Python generator, declared read-only.
- `alias-contract` — fails when `pyproject.toml` or Devtool package expectations drift from the canonical alias registry.
- `refresh-install` — read-only with respect to repository content; refreshes the external editable Python installation only after generated-surface checks pass.
- `machine-contract` — deterministic R08+ schema/capability/package-data consistency check, declared read-only.
- `provenance-contract` — deterministic R09A logical-fingerprint/diff/schema/alias/package consistency check, declared read-only.
- `remote-contract` — deterministic R09B remote-capability schema/publication/docs/Devtool consistency check, declared read-only.
- `r09b-gate-contract` — deterministic cumulative R09B promise-ledger/workflow/profile boundary check, declared read-only.
- `r10-gate-contract` — deterministic cumulative R10 promise-ledger/workflow/profile boundary check, declared read-only.
- `r11-gate-contract` — deterministic cumulative R11 provenance/diagnostic/workflow/profile boundary check, declared read-only.
- `r12-contract` — deterministic R12 advisory/benchmark/diagnostics machine/schema/privacy/Devtool ownership contract, declared read-only.
- `backend-smoke` — deterministic native backend round-trips with structured evidence at `.devtool/evidence/backend-smoke.json`.
- `release-evidence` — hashes produced wheel/sdist artifacts and the committed completion into `.devtool/evidence/release-contract.json`.

The repository scheduler enables safe parallel workflow execution with a maximum of three nodes. Devtool still applies dependency, read/write-scope, and resource conflict checks, so unknown/conflicting writers serialize automatically.

## Termux-safe validator policy

The repository intentionally does not install Ruff or pytest-cov into Devtool's managed venv on native Termux. Termux already ships Ruff as a native package, so the repository calls the host `ruff` executable directly from EXO target-local command jobs. This preserves Devtool's venv isolation for project/test/package dependencies while avoiding a redundant pip/maturin Rust build. `./devtoolw check` and `./devtoolw quality` are the authoritative quality gates; raw `devtool validate --target arc` remains available for Devtool's Python build/test/package validation but does not attempt venv-module Ruff execution. The only declared validator dependency is the pure-Python `build` frontend.


## ARC final gate and seal

The campaign qualification is wrapper-first. Use the repository entry points rather than calling gate scripts directly:

```sh
./devtoolw gate
./devtoolw seal
```

`gate` executes the `final_gate` EXO workflow: syntax/source-hygiene checks, completion and repository-contract checks, then the complete R01-R12 pytest campaign gate including native-backend qualification, machine/transport/mutation/config/advisory gates, and package verification. `seal` executes `final_seal`, which repeats the gate, runs Devtool's own `wrapper seal`, and generates/verifies a schema-5 live content ledger from the exact post-gate transaction tree. `release/ARC-FINAL-SEAL.json` is a static schema-7 R01-R12 seal contract included in that content root. The artifact `before_commit` finalizer is read-only: it re-verifies the exact candidate ledger from validation before Devtool is allowed to commit.
