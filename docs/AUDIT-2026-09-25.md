# Implementation audit — 2026-09-25

The initial implementation passes its existing 14-test suite, but a contract-level audit found behavior that still needs remediation before v0.1.0 should be considered fully qualified.

## Confirmed gaps

- Normalized include/exclude selection is implemented for creation/mutation but not consistently for `list`, `extract`, and `test`.
- `list` bypasses the normal backend execution path, so backend-specific arguments after `--` and `--show-command` are not honored there.
- Stream extraction conflict semantics are inconsistent; `--skip-existing` can still overwrite an existing stream target.
- `--dry-run` is not fully side-effect-free when `--rename-existing` is involved.
- `add` versus `update` semantics are not yet normalized consistently across all backends.
- Some compressed single streams containing TAR-like zero blocks can be misidentified as compressed TAR.
- RAR safety metadata is weaker when the available native lister does not expose link/special-object information.
- The generated Zsh completion is useful but is not yet fully command/context-specific and still uses newline-oriented candidate protocols in places where NUL-safe transport was promised.
- The full format × operation × backend qualification matrix, odd-filename tests, interruption tests, and interactive fzf/Yazi runtime tests are not yet present.
